# History Timeline API

Интерактивная платформа для визуализации и анализа исторических процессов, предоставляющая REST API с поддержкой иерархических связей событий, хронологической фильтрации диапазонов, пролептического григорианского и юлианского календарей, а также строгим контролем целостности данных на уровне СУБД.

---

## 1. Технологический стек

- **Язык и среда исполнения:** Python 3.14.7
- **Веб-фреймворк:** FastAPI (полностью асинхронный)
- **База данных:** PostgreSQL 18
- **ORM и драйвер:** SQLAlchemy 2.0 (асинхронный движок) и asyncpg
- **Валидация данных и конфигурация:** Pydantic v2 и pydantic-settings
- **Управление миграциями:** Alembic
- **Статический анализ и стиль:** Ruff (линтер и форматтер, профиль py314)
- **Тестовый контур:** Pytest, pytest-asyncio, pytest-cov, asgi-lifespan, httpx

## 2. Первичная настройка локального окружения

### Клонирование репозитория
```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd history_timeline
```

### Создание и активация виртуального окружения

Рекомендуется использовать изолированное виртуальное окружение на базе Python 3.14.7.

**Для Windows (PowerShell):**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

> **Примечание:** Если выполнение скриптов отключено в Windows PowerShell, выполните предварительную команду:
> `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process`

**Для Linux / macOS (Bash / Zsh):**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Установка зависимостей проекта

Обновите пакетный менеджер `pip` до актуальной версии и выполните установку продуктовых и dev-зависимостей:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt -r requirements-dev.txt
```

### Настройка переменных окружения

Скопируйте эталонный файл конфигурации окружения `.env.example` в рабочий файл `.env`:

**Для Linux / macOS:**
```bash
cp .env.example .env
```

**Для Windows (PowerShell / CMD):**
```powershell
copy .env.example .env
```

Отредактируйте параметры подключения в созданном файле `.env` в соответствии с вашей локальной конфигурацией PostgreSQL 18:

| Переменная | Назначение и описание | Значение по умолчанию |
| --- | --- | --- |
| `DB_HOST` | Сетевой хост сервера PostgreSQL | `127.0.0.1` |
| `DB_PORT` | Порт подключения к СУБД | `5432` |
| `DB_USER` | Имя пользователя (роли) базы данных | `postgres` |
| `DB_PASS` | Пароль пользователя базы данных | `postgres` |
| `DB_NAME` | Название основной базы данных приложения | `timeline_db` |
| `TEST_DB_NAME` | Название изолированной базы данных для запуска pytest | `timeline_test_db` |
| `APP_ENV` | Режим работы приложения (`development`, `testing`, `ci`, `production`) | `development` |
| `SECRET_KEY` | Криптографический ключ подписи токенов и сессий | `secret-key-change-in-production` |

> **КРИТИЧЕСКОЕ ПРЕДУПРЕЖДЕНИЕ ПО БЕЗОПАСНОСТИ:**
> Файл `.env` содержит конфиденциальные учетные данные и пароли доступа к инфраструктуре. Категорически запрещено добавлять и коммитить файл `.env` в систему контроля версий Git. Файл надежно изолирован правилом в `.gitignore`.

### Инициализация баз данных и применение миграций

1. **Создание основной базы данных:**
   Создайте основную базу данных `timeline_db` с помощью консольного клиента `psql` или встроенной панели Database в PyCharm:
   ```sql
   CREATE DATABASE timeline_db WITH OWNER postgres ENCODING 'UTF8';
   ```

2. **Применение схемы базы данных через Alembic:**
   Накатите актуальное состояние структуры реляционных таблиц, триггеров и ограничений целостности:
   ```bash
   alembic upgrade head
   ```

3. **Инициализация тестовой базы данных:**
   Перед первым запуском тестового контура запустите системный скрипт автоматического создания тестовой базы данных `timeline_test_db`:
   ```bash
   python scripts/create_test_db.py
   ```

## 3. Запуск сервиса

Запуск локального сервера разработки под управлением ASGI-сервера Uvicorn:

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

После успешного старта сервиса доступны следующие сетевые интерфейсы:

- **Интерактивная документация Swagger UI:** [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- **Альтернативная документация ReDoc:** [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)
- **Точка контроля состояния сервиса и подключения к БД (Health Check):** [http://127.0.0.1:8000/api/v1/health](http://127.0.0.1:8000/api/v1/health)
- **Клиентский веб-интерфейс Single Page Application:** [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

## 4. Контроль качества и стиля кода

В проекте используется сверхбыстрый статический анализатор и форматтер **Ruff**, настроенный под синтаксические стандарты Python 3.14.

- **Комплексная проверка кодовой базы (линтер):**
  ```bash
  ruff check .
  ```

- **Проверка соблюдения стандартов форматирования без изменения файлов:**
  ```bash
  ruff format --check .
  ```

- **Автоматическое форматирование кода в соответствии со стандартами:**
  ```bash
  ruff format .
  ```

## 5. Тестирование и метрики покрытия

Проект снабжен двухуровневым контуром автоматизированного тестирования (модульные и сквозные интеграционные тесты с реальной СУБД).

- **Запуск полного набора тестов с консольной сводкой:**
  ```bash
  pytest
  ```
  *(Лог выполнения теста, детали миграций и сводка покрытия автоматически дублируются без ANSI-кодов в файл `project_info/pytest_last_run.txt`)*.

- **Генерация детального интерактивного HTML-отчета покрытия:**
  ```bash
  pytest --cov-report=html
  ```

- **Просмотр отчета покрытия:**
  Сформированный отчет открывается в браузере по пути:
  ```text
  htmlcov/index.html
  ```
  Нормативный порог шлюза качества (Coverage Gate) составляет не менее **80%** (текущее достигнутое покрытие кодовой базы превышает **92%**).

## 6. Архитектурная структура каталогов

```text
history_timeline/
├── app/                  # Ядро серверного приложения
│   ├── api/              # Транспортный уровень: роутеры, контроллеры эндпоинтов v1
│   ├── core/             # Системные синглтоны: конфигурация, enum, исключения, логгер, пул БД
│   ├── crud/             # Низкоуровневый уровень доступа к данным (Data Access Layer)
│   ├── models/           # Декларативные ORM-модели SQLAlchemy 2.0
│   ├── schemas/          # Контракты валидации запросов и сериализации ответов Pydantic v2
│   ├── services/         # Сервисный слой бизнес-логики и иерархических инвариантов
│   └── main.py           # Точка сборки ASGI-приложения FastAPI, middleware и SPA fallback
├── frontend/             # Клиентский интерфейс Single Page Application (HTML5/ES6 modules/CSS)
│   ├── css/              # Таблицы стилей оформления интерфейса
│   ├── js/               # JavaScript-модули представлений, API-клиента и маршрутизатора
│   └── index.html        # Базовый каркас точки монтирования SPA
├── migrations/           # Версионированные скрипты миграций схемы базы данных Alembic
│   ├── versions/         # Линейная цепочка ревизий миграций
│   └── env.py            # Конфигурация запуска мигратора с безопасной передачей DSN
├── project_info/         # Регламенты, аудит безопасности и сохраненные логи прогонов
├── scripts/              # Инженерные утилиты (create_test_db.py, benchmark_range_query.py)
├── tests/                # Тестовый контур pytest
│   ├── conftest.py       # Корневые фикстуры, перехватчик вывода в файл и LifespanManager
│   ├── integration/      # Интеграционные тесты взаимодействия с PostgreSQL 18
│   └── unit/             # Изолированные юнит-тесты модулей API и сервисов с моками
├── .env.example          # Шаблон переменных окружения для локальной разработки
├── alembic.ini           # Конфигурационный файл инструмента миграций Alembic
├── pyproject.toml        # Метаданные сборки проекта, конфигурация Ruff, pytest и coverage
├── requirements.txt      # Зависимости среды исполнения (FastAPI, SQLAlchemy, asyncpg и др.)
└── requirements-dev.txt  # Зависимости среды разработки и тестирования (pytest, ruff и др.)
```
