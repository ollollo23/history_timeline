ПОШАГОВЫЙ РЕГЛАМЕНТ ФИКСАЦИИ И ВЫГРУЗКИ РЕЛИЗА
=======================================================

1. СТАТИЧЕСКИЙ АНАЛИЗ И СТИЛЬ КОДА

Блок 1: Серверный контур (Python / Ruff)
Автоматическое форматирование и проверка серверного кода Python 3.14:
ruff format .
ruff check --fix .
ruff check .
ruff format --check .
Требование: команды ruff check и ruff format --check обязаны завершаться с кодом 0.

Блок 2: Клиентский контур (JavaScript / ESLint 9 Flat Config)
Статический анализ модулей ECMAScript и автоматическое исправление:
npm run lint
npm run lint:fix
Требование: проверка линтера обязана завершаться с кодом 0 без ошибок и предупреждений (no-unused-vars, синтаксис ES-модулей, изоляция глобальных контекстов).

2. МИГРАЦИИ СХЕМЫ БАЗЫ ДАННЫХ (ALEMBIC)
Актуализация реляционной структуры таблиц PostgreSQL 18:
alembic upgrade head

3. КОМПЛЕКСНАЯ ВЕРИФИКАЦИЯ ЭТАПА РАЗРАБОТКИ

Быстрый запуск сквозного контроля качества (единый оркестратор):
npm run check:all
(или прямой вызов: python scripts/record_all_checks.py)
Команда последовательно выполняет:
1. ruff check . -> project_info/ruff_check_last_run.txt
2. ruff format --check . -> project_info/ruff_format_last_run.txt
3. npm run lint -> project_info/eslint_last_run.txt
4. npm test -> project_info/npm_test_last_run.txt
5. pytest -> project_info/pytest_last_run.txt
Все 5 протоколов в каталоге project_info обновляются автоматически с удалением ANSI-последовательностей.

Блок 1: Серверный тестовый контур (Python / Pytest)
Команда ручного исполнения:
pytest
Требования к результату:
— 100% тестов завершены со статусом PASSED (115 модульных и интеграционных тестов).
— Общее покрытие кодовой базы не ниже установленного барьера 80% (текущее покрытие > 92%).
— Автоматическое дублирование терминального лога в файл project_info/pytest_last_run.txt фикстурой TeeWriter.

Блок 2: Клиентский тестовый контур (JavaScript / Vitest)
Команда ручного исполнения:
npm test
Требования к результату:
— Успешное прохождение всех 6 тестовых наборов (105 тестов, Failed Tests: 0):
  tests/js/calendar.test.js (календарная арифметика Говарда Хиннанта)
  tests/js/scale.test.js (геометрические проекции и логарифмический масштаб)
  tests/js/viewport.test.js (модель камеры и инвариант масштабирования к курсору)
  tests/js/ticks.test.js (лестница шагов сетки и синхронизация констант с бэкендом)
  tests/js/format.test.js (форматирование подписей делений, шкал и интервалов)
  tests/js/controller.test.js (инвариант направления зума и чистый расчет дельты колеса)

Блок 3: Ручная проверка интерактивного интерфейса в браузере
Запуск локального сервера разработки:
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
Адрес проверки: http://127.0.0.1:8000/

Порядок ручного тестирования рабочей области таймлайна:
— Загрузка страницы: появление зеленого бейджа связи с API и корректное отображение холста Canvas высотой 320 пикселей.
— Панорамирование: горизонтальное перетаскивание холста мышью (drag-and-drop), смена курсора с grab на grabbing, плавное смещение делений сетки.
— Картографическое масштабирование: прокрутка колеса мыши вверх (от себя) приближает масштаб (уменьшает интервал), прокрутка вниз (на себя) отдаляет масштаб; точка под курсором (anchor) строго сохраняет временную координату.
— Выравнивание до нашей эры: деления сетки до н. э. кратны круглым историческим датам (1000, 10000, 100000 лет до н. э.) без дробных хвостов.
— Информационная панель: обновление видимого диапазона дат и текущего масштаба в тулбаре под холстом через requestAnimationFrame без микрофризов и layout thrashing.
— Кнопка сброса: нажатие на кнопку "К началу" центрирует камеру и возвращает шкалу к базовому 200-летнему обзору.
— Консоль разработчика (F12): полное отсутствие ошибок выполнения JavaScript, предупреждений переполнения и сбоев загрузки статических модулей.

4. КОНТРОЛЬ СТАТУСА, АУДИТ МАНИФЕСТОВ И ФИКСАЦИЯ В GIT

Проверка целостности манифеста блокировок:
Убедиться, что файл package-lock.json физически присутствует в корне проекта и отслеживается Git.
Отсутствие package-lock.json приведет к аварийному завершению шага npm ci в конвейере GitHub Actions.

Проверка обновления аудиторских отчетов в project_info/:
Убедиться, что обновлены все 5 файлов протоколов:
— project_info/ruff_check_last_run.txt
— project_info/ruff_format_last_run.txt
— project_info/eslint_last_run.txt
— project_info/npm_test_last_run.txt
— project_info/pytest_last_run.txt

Проверка статуса рабочего дерева Git:
git status

Индексация всех проверенных модулей и артефактов:
git add .

Создание атомарного коммита по конвенции Conventional Commits:
git commit -m "feat(timeline): завершение стабилизации клиентского ядра и интеграция контроля качества"

5. ВЫГРУЗКА В УДАЛЕННЫЙ РЕПОЗИТОРИЙ GITHUB
Отправка зафиксированных изменений в основную ветку:
git push origin master

6. РУЧНОЕ ПОДТВЕРЖДЕНИЕ В GITHUB ACTIONS (CD)
— Перейти в репозиторий проекта на GitHub -> вкладка Actions.
— Открыть текущий запуск конвейера CI/CD.
— Дождаться успешного прохождения заданий lint, guard и test.
— Нажать Review deployments на шаге production.
— Выбрать окружение production и нажать Approve and deploy.
